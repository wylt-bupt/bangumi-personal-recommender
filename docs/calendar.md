# 我的放送表

开发遵循根目录 [AGENTS.md](../AGENTS.md)。组件独立于推荐/回顾与活跃度热力图，当前版本取自 `package.json.calendarVersion`。

## 数据与显示口径

只显示当前登录用户动画收藏与 Bangumi 每周放送表的 ID 交集。同步保存五种收藏状态，展示时排除“看过”（type 2），其余四种状态参与匹配，不提供状态开关；没有评分、国家、篇幅或作品形式条件，不进行系列归并或同名匹配。中文名缺失时用原名。标题用 DOM `textContent` 写入，封面仅接受 `lain.bgm.tv` 的 HTTP/HTTPS 地址并规范为 HTTPS；图片失败显示“暂无封面”。

首页默认读取 `https://api.bgm.tv/calendar`，失败时读取同源 `/calendar` HTML。完整放送页直接解析页面七个星期的条目，手动刷新时重新读取同源页面。公开收藏使用 `/v0/users/{username}/collections?subject_type=2&limit=100&offset=…`，每页校验总数、偏移与 ID；缺页、重复 ID 或同步期间总数变化均报错，不能将部分结果当作成功的空收藏。

站内模式使用 `credentials: same-origin` 读取本站五种收藏列表 `wish/collect/do/on_hold/dropped`。验证当前登录账号、目标用户、列表容器、状态总数及相邻页链接，读取所有页后一次性替换结果。公开 API 不能自动读取私密收藏，组件不申请或保存 Token。站内/公开模式按账号记住；新用户默认使用公开 API。私密数据只留在该站点的浏览器存储中，不上传到仓库或第三方。

收藏缓存仅保存 `{id,type}`；舍弃 API 的评分、评论、标签、私密标志等字段。缓存隔离于站点 origin 和账号，公开/站内模式分别保存；公开与站内收藏缓存不定时过期：存在有效缓存时自动打开只读缓存，首次无缓存/缓存损坏或用户手动刷新才完整同步。首页放送安排一小时内不联网，超过一小时先同步显示旧缓存，再单独在后台更新放送表；完整放送页优先同步解析当前页面，不为日期安排再发请求。逐页请求间隔 180ms，请求超时 20 秒；没有后台定时网络轮询。浏览器存储失败时继续内存展示，但下一次打开因无法持久化缓存而需要重新同步。缓存不保存生成的日期，打开时始终按当前日期重新排列表。收藏缓存沿用 v1 键，无需升级后重新采集；新增收藏、移除收藏及改成看过等状态在用户点击刷新后生效。

日期按浏览器当地日期生成，日期导航固定显示选中日期所在周的周一至周日。默认选中今天，桌面三列显示昨天、今天、明天，今天单独加粗；窄屏按可用列数围绕选中日期显示。点击星期可选择该周日期，左右箭头每次只将选中日期前移或后移一天；跨周时导航仍按周一至周日排列。日期浏览只切换本地已加载的星期表和收藏交集，不发网络请求；这只是星期放送安排，不是逐集的实时上线表，不推算集数、具体时刻、停播或完结。标题旁始终显示实际“今天 · 周几”，点击可从任意周返回今天。跨午夜的本地单次定时器与页面恢复可见时都会更新今天；未手动浏览时选中日期跟随今天，手动浏览时保留选择。放送表可能暂时包含已完结作品，已标“看过”的条目不展示；收藏状态核对后生效，不依据播出集数猜测是否看完。

## 挂载与视觉

- 首页挂载在 `#home_calendar` 内；有有效放送/收藏缓存时，在组件初始化的同一任务内生成个人列表并隐藏原有子节点；没有数据时保留原始视图，同步成功后再隐藏，不删除原 DOM。
- 完整页面挂载在 `.BgmCalendar` 的 `.columns` 容器内，保留原有宽度与外围标题。`/calendar?personal=off` 完全保留原始页面，不读缓存或 API。
- Shadow DOM 隔离样式。容器宽度决定列数：首页最多三列、完整页最多四列；窄屏单列。标题自动换行，不在悬浮提示里隐藏中文名称；封面保持比例，不裁掉海报。外框使用 15px 圆角，与实际首页 `#prgManager` 和原生 `.SidePanelMini` 一致。实际今天在放送列中以粉色线和“今天”文字强调；标题旁的今天定位入口不随选中日改变。
- 周一至周日日期按钮、逐日箭头、今天定位入口和唯一数据操作“刷新核对个人收藏”均可用键盘；重绘日期保留焦点。遵循 Bangumi `data-theme`，没有显式主题时跟随操作系统。没有动效、浮层、外部字体或新增运行依赖。
- 未登录、非首页/放送页不挂载或请求数据。首次失败保留原始界面；有缓存时保留缓存与原核对时间并显示错误；失败刷新不清空已有收藏。

## 放送日与自然日期（2026-10-04 核对）

[日本2026年秋季动画](https://zh.moegirl.org.cn/日本2026年秋季动画) 页首明确使用日本时间 UTC+9 和深夜动画的 30 小时表示法：周四 25:00 即自然日期周五 01:00，列表归入周四；北京时间对应周五 00:00。例如页面“某暗部的少女共栖”列每周五 24:30，即日本周六 00:30、北京时间周五 23:30，放送槽仍归周五。不能仅凭“凌晨”二字决定移到前一天，必须核对时区与原始放送日/时刻。

组件当前按 Bangumi `/calendar` 的 weekday 分组，不抓取萌娘百科、不猜测具体时刻，也不把本地日期当成精确上线时间。官方放送 API 没有准确的小时分钟和统一时区字段，无法从现有星期数据自动重算北京时间星期。当前日期用于导航及今天定位，条目分组来自 Bangumi 的每周放送安排；两者不能混称为逐集上线日历。萌娘页面部分条目没有时刻且提示存在未证实内容，不能用它批量覆盖 Bangumi。

## 1.0.6 的加载与缓存决策

旧版首次渲染等待 `getCalendar()` 和 `getCollections()` 顺序完成，收藏六小时过期后会再次遍历所有页；网络等待发生在首屏之前，即使最后回退缓存也会迟到。新版区分变化频率：个人收藏使用缓存优先且手动失效，放送安排先展示缓存、超过一小时才后台更新。沿用 [Chrome 官方缓存策略说明](https://developer.chrome.com/docs/workbox/modules/workbox-strategies#stale-while-revalidate) 的先响应缓存/后台更新思路，按用户要求为收藏取消定时核对；不引入 Workbox、Service Worker 或新依赖。

初始化先验证所记住的来源缓存并同步渲染；有缓存的收藏不读取 API 或收藏 HTML，缓存原核对时间不滑动、不在每次打开时重写。完整放送页可立即解析当前 HTML，首页读取独立放送缓存。后台只请求放送安排，不锁住手动刷新入口；手动同步启动后，旧后台响应不能再写 UI 或缓存。手动同步完整验证成功后更新收藏/放送缓存，失败保留旧列表。有效空收藏也属于可用缓存；损坏或被清除的收藏缓存才触发首次完整同步，账号及来源继续隔离。

隔离浏览器使用阻塞放送请求验证首屏在网络返回前已可见，覆盖十天旧收藏、5014 条成员、站内私密成员及空缓存；再次打开没有收藏请求、原收藏核对时间保持不变。后台放送失败仍保留列表；较迟的后台响应无法覆盖手动新结果；既有桌面/窄屏、暗色、午夜和同步失败场景全部通过。

此处的立即显示指组件开始运行后无需等待网络。Bangumi 自身载入页面与组件脚本的时间、尚未缓存的封面下载仍由浏览器和网络决定；不声称整个网页或图片零延迟。
