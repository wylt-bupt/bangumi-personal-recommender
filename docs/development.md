# 开发与维护

开发前先读根目录的 [AGENTS.md](../AGENTS.md)。六条用户设计原则在那里完整保存，是本项目的唯一规范正文；本文解释实际代码、验证与交付入口，不另造一套原则。

## 目录与边界

```text
AGENTS.md                   用户设计原则与交付要求
README.md                   当前功能、版本和文档导航
src/                        当前组件
scripts/                    构建、浏览器验收工具
tests/                      当前实现测试与本地夹具
demo/                       预览导航、组件预览、发布源码页
dist/                       可直接发布的构建产物
docs/                       维护说明与旧版本说明
experiments/                按日期保存的方法、结果与复现代码
legacy/                     旧推荐源码、测试与备份
```

采集缓存位于 `scripts/.cache/`，试验大数据位于各试验的 `data/` 或已忽略快照中，截图位于 `artifacts/`；这些文件不提交。不为未来可能的功能创建空目录或文档框架。

## 当前实现

| 入口 | 责任 |
| --- | --- |
| `src/profile-ui.js` | 精确限定 `wylt` 主页，挂载、主题、懒加载与共享样式 |
| `src/recommender-core.cjs`、`src/recommender.js` | 标签分数库、评分与选优（纯函数）；手动刷新的采集编排与动画/书籍双模块展示 |
| `src/stats-core.cjs`、`src/stats-viz.cjs`、`src/stats.js` | 独立动画回顾：年代与标签、创作、声优排行 |
| `src/timeline-core.cjs`、`src/timeline.js` | 独立活跃度热力图；只统计看过的集数，不统计收藏操作次数 |
| `src/calendar-core.cjs`、`src/calendar.js` | 独立个人放送表；七天放送表与当前登录用户收藏的 ID 交集，展示时排除看过 |
| `src/series-family.cjs`、`scripts/family-folds.cjs` | 离线评测的系列分组；不包含旧推荐资格规则或权重 |
| `scripts/refresh-recommendations.cjs`、`scripts/build-recommendations.py` | 限速读取公开数据，比较模型，生成聚合清单 |

构建只打包当前网页模块；旧协同过滤管线（月度采集、模型训练、聚合清单）已在推荐 1.0.0 退役，历史实现见 [legacy 说明](../legacy/README.md)，实验状态见 [实验索引](../experiments/README.md)。历史文件里的“当前”“主模型”只指当时版本。

## 修改与验收

1. 确认需求和实际口径。算法调整先研究可靠实践，说明数据、候选范围、基线与局限；界面调整先核对用户认可的风格和交互。
2. 只改相关模块，保留用户已有修改；原始评分、缓存和凭据不得进入 Git。不为目录好看制造抽象。
3. 执行 `npm run verify`：重建产物、语法检查、当前测试、历史兼容测试。`npm test` 只验证当前实现；`npm run test:legacy` 单独验证归档源码，避免把旧口径当成当前产品规则。
4. 按风险做浏览器验收。使用者视角检查窄屏/暗色、分页、解释、隐藏撤销、错误回退与数据口径；实现者视角检查请求数量、训练是否泄漏到网页、包体积、依赖和维护成本。目录整理尤其检查链接、相对导入和夹具入口。
5. 更新文档，只声称实际验证过的结果。版本以 `package.json` 为准，源码辅助页从构建头读取版本；本地构建与远程清单不能混称为已上线。

本地预览：执行 `python -m http.server 8765 --bind 127.0.0.1`，打开 `http://127.0.0.1:8765/demo/`。导航页包含个人主页、热力图、放送表、分页夹具及四个发布源码页。源码页只是复制入口，不会自动发布到 Bangumi；预览不修改线上收藏，但演示封面可能请求 Bangumi 图片服务。

`demo/profile.html` 使用演示推荐与回顾数据；分页夹具禁止真实 API/清单请求。`demo/timeline.html` 只验证本地挂载、读取该本地站点的已有缓存，不自动采集或造出观看记录；首次没有缓存时会保持“正在整理”外壳，不能把它算成完整热力图验收。完整解析/同步/绘图测试使用下述隔离夹具脚本。

`scripts/test-profile-browser.cjs`、`scripts/test-stats-viz-browser.cjs`、`scripts/test-timeline-browser.cjs` 为隔离浏览器回归脚本，需要外部安装的 `playwright` 和 Chrome，不是组件运行依赖，不包含在 `npm run verify` 中。前两者需要本地服务器；热力图脚本通过请求夹具独立运行。浏览器与电脑交互工具选择遵循 [AGENTS.md](../AGENTS.md#浏览器与电脑交互工具)，不用这些脚本接管用户的登录浏览器。

`node scripts/test-profile-cache-browser.cjs` 独立运行，无需本地服务器；其网络全部由夹具接管，验证推荐与回顾的真实构建脚本、长期缓存、挂载零请求、手动刷新全流程（收藏→标签库→候选池→关联复核）、失败保留与关联缓存复用，不使用演示页面的推荐结果覆盖逻辑。

## 数据刷新与交付

推荐组件使用 localStorage `bgmpr:v3:*` 缓存键（收藏带标签、两份结果、关联缓存），不迁移或上传个人原始记录；旧 `bgmpr:v2:*` 键在挂载时清除。挂载零网络请求，只渲染缓存结果；「更新」按钮按限速依次核对公开收藏（动画/书籍分开，读取每部作品的全站用户标签）、分页读取全站排行候选（评分人数 ≥ 500）、本地打分排序并逐个复核「不同演绎」关联（缓存 30 天），取满动画 30 部 / 书籍 20 部。失败保留上次结果并提示；不存在自动或定时刷新，也没有任何远端清单。回顾组件使用 `bgmpr-stats` IndexedDB 缓存键，不迁移或上传个人原始记录。回顾在挂载时读取本地收藏，先显示年代/标签，随后批量读取人物缓存。首次没有有效收藏缓存才自动采集；存储不可用时仍可能在下次打开重新同步。

回顾在创作/声优页手动补全人物关联；已有且超过 90 天的人物缓存仍供展示，只有显式补全时更新过期/缺失关联。人物本地读取按类别使用一个只读事务，避免为每条收藏创建事务。收藏分页验证成功后才覆盖缓存。

缓存策略参考 [Chrome 官方 Cache First 与后台更新说明](https://developer.chrome.com/docs/workbox/modules/workbox-strategies)，仅使用该思路，不引入 Workbox、新依赖或 Service Worker。这里的快速加载指组件启动后不等待收藏网络遍历；Bangumi 页面/脚本和未缓存图片自身的加载仍有网络成本。两个模块继续限定在 `wylt` 个人主页，推荐模型、收藏排除口径和独立热力图/放送组件保持各自原有职责。

“我的放送表”使用 `package.json.calendarVersion` 和 `scripts/build-calendar.mjs` 独立构建，产物为 `dist/bangumi-personal-calendar.user.js` 与逐字相同的 `.bgm.txt`。浏览器回归为 `node scripts/test-calendar-browser.cjs`（隔离请求夹具，不需本地服务器）；预览与源码入口为 `demo/calendar.html`、`demo/calendar-source.html`。数据来源、私密同步、缓存和失败边界见 [放送组件说明](calendar.md)。独立发布至 [应用 7211](https://bgm.tv/dev/app/7211)，不占用应用 6931 或 7057。

“动画回顾”使用 `package.json.statsVersion` 和 `scripts/build-stats.mjs` 独立构建，产物为 `dist/bangumi-personal-stats.user.js` 与逐字相同的 `.bgm.txt`；发布源码页为 `demo/stats-source.html`，独立发布至 [应用 7382](https://bgm.tv/dev/app/7382)。个性推荐（`scripts/build.mjs`，`version`）与回顾共享 `src/profile-ui.js` 挂载助手，各自内嵌一份；页面顺序由挂载区 flex order 决定（回顾 10、推荐 20），缓存键不相交。

- 产品变更遵循 [AGENTS.md](../AGENTS.md)：验证、受影响版本、README、构建、提交、推送、Bangumi 个人开发版本保存与线上验收，未经用户明确要求不提交全站审核。应用 6931 对应个性推荐，7382 对应动画回顾，7057 对应热力图，7211 对应放送表；推荐、回顾与放送表各自的 `.user.js` 与 `.bgm.txt` 必须一致。
- 纯文档或行为不变的目录整理仍验证、提交、推送；若 `dist/` 和聚合清单逐字未变，就没有需要升级或重发的组件版本。

## 2026-10-24 维护记录（四）：个性推荐 1.0.0 标签均分制重写

个性推荐 `1.0.0`（2026-10-24）：应用户规格彻底重写——旧协同过滤推荐（月度采集、公开用户样本、预测模型、聚合清单、六小时后台检查）整体退役，改为最简单的本地评分推荐。退役文件 18 个：`src/recommender-v2.js`、`recommendation-feed.cjs`、`candidate-eligibility.cjs`、`series-family.cjs`、月度脚本五个、`data/peer-cohort.json`、`public/recommendations.json`、`.github/workflows/monthly-recommendations.yml` 及六个配套测试；净删约 4400 行。

评分规则（用户原文逐条落地）：从我评过分的条目（打分即可、不限收藏状态）身上的**全站用户标注标签**建标签分数库——我的 10 分制评分即标签在该作品下的得分，标签分数取均分；候选的标签分 = 其所有用户标签的标签分数均分 ÷ 2（1-5），全站分 = 全站评分 ÷ 2，**推荐评分 = 两项平均保留 2 位小数**；候选池 = 全站排行中评分人数 ≥ 500 且我未打分的条目（仅收藏未评分照常参与），排除 OVA 与关联条目中存在我已评分作品且关系为「不同演绎」者。动画 30 部、书籍 20 部分模块列出，共用同一评分标准。

实现：`src/recommender-core.cjs`（纯函数：buildTagDb/tagScore/scoreCandidates/selectTop）+ `src/recommender.js`（采集编排与双模块 UI）。手动更新按 250ms 限速执行：收藏分页（动画/书籍分开，行内 `subject.tags` 即全站标签）→ 标签库 → 排行分页候选（每页 100，整页人数 < 500 或 50 页封顶）→ 打分排序 → 按得分从高到低逐个查 `/v0/subjects/{id}/subjects` 复核「不同演绎」（结果缓存 30 天于 `bgmpr:v3:relations`），取满限额即停。挂载零网络请求，只渲染 `bgmpr:v3:result:*` 缓存；旧 `bgmpr:v2:*` 键挂载时清除。卡片只保留封面、名字（链条目页）、推荐评分与一行小字（全站评分/标签评分，1-5 两位小数）；每页 5 部，分页交互沿用旧版；失败保留上次结果并提示。

## 我的放送表 1.0.8：收藏核对不再被放送表挡住

用户报告已取消收藏的《青之箱 第二季》仍出现在放送表，点“更新”既无报错也无变化。实证过程：kimi 浏览器接管作者已登录的 bgm.tv 标签页读 localStorage，`collections:public` 停在 2026/10/7 00:43（1379 条，含 548156，type 3），`calendar` 为 10/17 23:23；同一上下文里请求 `https://api.bgm.tv/v0/users/wylt/collections/548156` 返回 404 `subject is not collected by user`，公开收藏总数 1372。即服务端早已没有该条目，组件却一直使用 11 天前的收藏快照。
