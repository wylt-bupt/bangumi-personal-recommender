# Bangumi 个性推荐

面向账号 `wylt` 的隐私优先超合金组件。它读取 Bangumi 收藏、评分、标签及可用的制作人员/声优关联，在全部已标记条目之外生成 5 个个性化推荐。

## 当前部署

- 源码主页：<https://github.com/wylt-bupt/bangumi-personal-recommender>
- Bangumi 组件：<https://bgm.tv/dev/app/6931>
- 当前版本：`0.10.5`，开发中，仅由组件创建者 `wylt` 启用，未提交全站审核。
- 在 `/user/wylt` 主栏“我的日志”后直接显示动画回顾和个性推荐；不再注入全站悬浮入口或侧边抽屉。

## 0.10.5 均分词云幂律字号

- “标签·个人均分”词云的字号映射从分位数 1.65 次幂改为 4 次幂：均分聚集在窄区间时，只有头部少数标签放大、长尾保持小字号（与“出现次数”词云一致的幂律观感），标签间差异清晰可辨，词云整体更紧凑。同分标签仍共享同一档位字号。

## 0.10.4 全量词云与边界修复

- 词云改为商业词云式有机排布：大词居中、其余阿基米德螺线向外，**所有**符合条件的标签在任何屏幕宽度下都完整展示，不再按宽度删减；单次有界排布 + 整体缩放保证收敛，消除极端标签集下的长时间阻塞。
- 词云容器恢复圆角矩形（不再用圆形裁切，边缘标签不再被切掉）；网格碰撞注册内边距大于碰撞间隙，杜绝相邻格子漏检导致的偶发重叠。
- 时间标签识别两处统一：`2024-07`、`2025夏`、`2024年7月番`、`2020s` 等形态不再混入画像特征与推荐卡片。
- 候选形式过滤加词边界：标题含“NOVA”等子串的条目不再被误判为 OVA/特别篇。
- 日本/外国判定对称化：地区字段按完整国家词条匹配，“日本／美国”合拍条目不再被直接误判为非日系（转入证据评分路径）。
- MMR 删除从未生效的同工作室惩罚死代码（多样性仍由特征 Jaccard 相似度承担）；特征向量构建去重，训练与打分全链路省去一半特征计算。
- API 断路器改为连续两次传输失败才跳闸、5 分钟冷却后自动试探恢复，单次网络抖动不再让整个会话退回站内解析。
- 动画回顾聚合结果按数据形状缓存，搜索输入与标签页切换不再每次全量重算；人物/来源补全的候选查找改为 Map，消除 O(n²)。

## 0.10.3 高密度词云

- 仅在窄屏空间不足时按实际文字面积动态精简；标签悬浮详情、均分层级与高低分代表性保持不变。

- 两种词云按实际文字面积动态保留优先级最高的标签，画布高度限制在宽度的 1.02—1.08 倍，不再为了塞入全部标签退化成长椭圆。

## 0.10.1 双词云轮廓统一

## 0.10.0 标签均分词云

- 每个标签的提示同时展示精确均分及已评分/总作品数，避免把未评分作品混入均分。

- 高频标签仍以字号、字重和中心位置表达权重；其余标签以确定性的轻微旋转、多方向螺旋与疏密变化形成更自然的构图。
- 旋转后的外接区域参与碰撞计算，避免文字遮挡；悬停、键盘焦点和减少动态效果仍然可用。

## 0.9.5 全局画像优先

- 个人评分按明确的绝对语义训练：7 分为中性，8 分及以上为喜欢，6 分及以下为不喜欢；站内评分只进入独立的质量校正，不再把“比大众评价高的 7 分”解释为喜欢。
- 删除近邻作品对推荐分数的影响，最终排序只由全量收藏学习的标签画像（80%）和贝叶斯质量分（20%）决定；相似作品仍可作为解释证据展示，不参与排序。
- MMR 在完整候选池上执行前先把适合度归一化到同一尺度，避免多样性惩罚压过实际相关性；统一排序后仍按每页 5 个展示。
- 五折离线实验中，删除近邻项后喜欢/不喜欢 AUC 从 0.8642 提升至 0.8676，折均前 20 命中率从 80% 提升至 83%。未采用会误伤《悠久之翼》等结果的标签票数校准。

## 已实现功能

- 支持动画、里番、书籍、游戏、音乐、三次元六类推荐；里番画像仅使用动画收藏中带“里番、裏番、步兵裡番、泡面里番、成人动画、R18、18X、18禁”等标签的条目。
- 自动排除想看、看过、在看、搁置和抛弃的全部条目。
- 单一推荐策略，类型选择器支持动画、里番、书籍、游戏、音乐和三次元，并可继续扩展特殊类型。
- 里番候选池会完整遍历“里番、裏番、步兵裡番、泡面里番、成人动画”标签页，并用 R18、18X、18禁补充召回；排序前会再次读取条目完整标签，宽泛或易误标的标签必须具备独立的色情内容或成人动画证据。R18、18X、18禁统一视为同一种年龄分级证据，不会互相佐证，以避免混入普通限制级作品和恶作剧误标。
- 模糊候选必须成功取得完整条目详情才可进入最终结果；最终成人向判定只读取独立保存的 API 原始详情，不读取召回阶段附加的来源标签。临时请求失败不会被缓存，也不会降级为仅凭来源标签入选。
- 查询标签、搜索 API 命中标签和站内标签页来源只用于召回，永不参与最终资格判断。成人类型会对初排前 360 名逐项读取 `/subjects/{id}` 完整详情；只有详情确认“里番、裏番、步兵裡番、泡面里番、成人动画”，或 R18、18X、18禁同时具备独立色情内容证据时，才进入最终池。
- 完整详情中的核心成人标签还会参考 Bangumi 标签投票数：达到 3 票视为稳定共识；低票标签仍需第二项成人证据，避免单人误标。
- 360 个详情复核名额中，180 个来自推荐初排，180 个按成人标签票数与交叉证据优先，从而在不增加请求上限、不改变最终评分的前提下提高可靠候选覆盖率。
- 推荐理由由模型贡献度自动生成，不接入 AI，也不上传个人数据。
- 推荐卡默认仅显示作品、标签与一句理由；展开后可查看推荐依据及预计评分。置信度计算仍保留在算法中，不占用日常界面。
- 卡片独立展示按重要性和文字预算动态挑选的内容标签；推荐依据聚焦相似高分收藏，仅在证据足够强时补充创作人员信息。
- 推荐排序恢复到最初 `0.1.0` 的评分、特征归一化与多样化基线，后续界面和书籍来源过滤独立于排序模型。
- 导演、制作公司、原作、脚本、音乐和声优等补充关联数据统一作为弱辅助证据：特征权重约为原先的三分之一，且补充评分只占最终综合分的 20%；MMR 继续使用补充前的内容特征，避免覆盖标签和评分形成的基础排序。
- 推荐分数只使用 Bangumi 的收藏状态、个人评分、条目标签、全站评分和站内关联数据；地区规则仅作候选资格过滤，不参与日本作品之间的排序。
- 所有类型只保留能由 Bangumi 标签、原名、制作机构或地区字段确认的日本作品；其他国家及来源不明的候选一律排除，不设破例。
- “暂时隐藏”只替换当前一批的该条目并提供 5 秒撤销，不写入画像，也不影响未来推荐分数。
- 使用 IndexedDB 缓存数据；收藏画像缓存 24 小时，候选缓存 3 天，人员信息缓存 30 天。
- “刷新画像”可立即忽略缓存，跟随最新收藏和评分重新计算。
- API 不可用时自动读取 Bangumi 站内收藏页、标签页和排行榜页。
- Shadow DOM 隔离样式，支持暗色模式、移动端、键盘操作和减少动态效果。
- 在 `wylt` 个人主页内嵌“动画回顾”；严格只统计标记为“看过”的动画，不依赖某个收藏列表页。
- 回顾展示倒序年份、数量大于 10 的个人标签，以及导演、系列构成、动画制作、原作/原案、脚本、音乐、角色设计和声优；不重复其他组件的评分分布或总览数字。
- 收藏索引按 12 小时缓存；人员和声优关联按 90 天缓存。首次只读取收藏索引，随后可低并发、暂停并从缓存续传地补全创作人员或声优数据。

## 推荐算法

1. 按个人评分的绝对语义训练偏好：7 分严格中性，8 分及以上为正向，6 分及以下为负向；全站评分不改变个人评分表达的正负。
2. 从标签、年代、条目形式、导演/作者、制作公司、脚本、音乐和声优构建稀疏特征；不同角色使用不同权重。
3. 对特征评分残差做带收缩的加权平均，并用 IDF 降低常见标签影响，避免只出现泛化标签。
4. 候选召回覆盖全站排名前 1000，以及个人前 12 个高权重标签各前 100 个条目；最终分数由全量收藏标签画像占 80%、贝叶斯质量分占 20%，相似作品只用于解释而不参与排序。
5. 最后把候选适合度归一化，再对完整高分候选池一次性执行 MMR 多样化；统一排序结果按每页 5 个展示，换页不会重新排序。

“适合度”和推荐理由都是本地确定性计算，不需要大模型。理由来自对最终得分贡献最大的特征；相似的高评分收藏可作为辅助解释，但不会改变推荐顺序。

## 数据来源

优先使用 Bangumi API：

- `GET /v0/users/{username}/collections`
- `GET /v0/subjects`
- `POST /v0/search/subjects`
- `GET /v0/subjects/{subject_id}/persons`
- `GET /v0/subjects/{subject_id}/characters`

若跨域 API 被浏览器或网络策略拦截，组件自动回退到同域的收藏列表、标签和排行榜页面。人员信息只在 API 可用时补充，因此回退模式仍可推荐，但导演、制作公司和声优理由可能较少。

## 安装与发布

开发时可以把构建产物导入支持 UserScript 的浏览器扩展进行测试。

作为 Bangumi 超合金组件发布时：

1. 打开 `https://bgm.tv/dev/app/create`，应用名填写“Bangumi 个性推荐”，类型选择“组件”。
2. 主页地址可以填写公开源码仓库；组件会访问 `api.bgm.tv`，因此需要勾选跨域请求声明。
3. 创建应用后点击“添加新版本”，把 `dist/bangumi-personal-recommender.user.js` 的完整内容粘贴到 JavaScript 编辑框并保存。
4. 前往 Bangumi 的“个人设置 → 超合金组件”启用最新版本，先以开发者身份验证。
5. 只有希望开放给其他用户时才选择“提交审核”；个人使用不需要提交审核。

Bangumi 会直接保存组件每个版本的 JavaScript/CSS，外部源码仓库用于主页、版本管理和审阅，并不是运行时依赖。

## 项目结构

- `src/core.cjs`：特征、画像、评分、解释和多样化算法。
- `src/component.js`：数据获取、缓存、交互和界面。
- `src/profile-ui.js`：主页挂载、共享样式与主题。
- `src/stats.js`：动画回顾内嵌组件。
- `src/stats-viz.cjs`：可单测的年代刻度与词云排布。
- `src/timeline-core.cjs`：个人时光机的解析、校验、去重与统计纯函数。
- `src/timeline.js`：个人时光机的同源同步、持久化与原版风格热力图界面。
- `scripts/build-timeline.mjs`：生成独立的个人时光机 UserScript。
- `scripts/build.mjs`：生成单文件 UserScript。
- `dist/bangumi-personal-recommender.bgm.txt`：与 UserScript 内容一致、便于在浏览器中粘贴发布的纯文本构建产物。
- `tests/core.test.cjs`：核心算法测试。
- `demo/index.html`：Chrome 可视化测试页。

## 隐私与限制

- 个人数据只保存在当前浏览器的 IndexedDB/localStorage。
- 组件不修改 Bangumi 收藏、评分或标签。
- 公开收藏不足 5 个有效评分时不会强行给出低可信推荐。
- 新评分会在手动“刷新画像”后立即生效；不手动刷新时，最迟在画像缓存过期后的下一次生成中生效。
