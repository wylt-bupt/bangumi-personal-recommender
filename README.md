# Bangumi 个性推荐

面向账号 `wylt` 的隐私优先超合金组件。它读取 Bangumi 收藏、评分、标签及可用的制作人员/声优关联，在全部已标记条目之外生成 5 个个性化推荐。

## 当前部署

- 源码主页：<https://github.com/wylt-bupt/bangumi-personal-recommender>
- Bangumi 组件：<https://bgm.tv/dev/app/6931>
- 当前版本：`0.2.9`，开发中，仅由组件创建者 `wylt` 启用，未提交全站审核。

## 已实现功能

- 支持动画、里番、书籍、游戏、音乐、三次元六类推荐；里番画像仅使用动画收藏中带“里番、裏番、步兵裡番、泡面里番、成人动画、R18、18X、18禁”等标签的条目。
- 自动排除想看、看过、在看、搁置和抛弃的全部条目。
- 单一推荐策略，类型选择器支持动画、里番、书籍、游戏、音乐和三次元，并可继续扩展特殊类型。
- 里番候选池会完整遍历“里番、裏番、步兵裡番、泡面里番、成人动画”标签页，并用 R18、18X、18禁补充召回；排序前会再次读取条目完整标签，宽泛或易误标的标签必须具备独立的色情内容或成人动画证据。R18、18X、18禁统一视为同一种年龄分级证据，不会互相佐证，以避免混入普通限制级作品和恶作剧误标。
- 模糊候选必须成功取得完整条目详情才可进入最终结果；最终成人向判定只读取独立保存的 API 原始详情，不读取召回阶段附加的来源标签。临时请求失败不会被缓存，也不会降级为仅凭来源标签入选。
- 推荐理由由模型贡献度自动生成，不接入 AI，也不上传个人数据。
- 推荐卡同时显示适合度和置信度百分比；置信度由偏好特征支持（50%）、相似收藏（30%）和全站评分样本（20%）构成。
- 卡片独立展示按重要性和文字预算动态挑选的内容标签；推荐依据聚焦相似高分收藏，仅在证据足够强时补充创作人员信息。
- 推荐排序恢复到最初 `0.1.0` 的评分、特征归一化与多样化基线，后续界面和书籍来源过滤独立于排序模型。
- 导演、制作公司、原作、脚本、音乐和声优等补充关联数据统一作为弱辅助证据：特征权重约为原先的三分之一，且补充评分只占最终综合分的 20%；MMR 继续使用补充前的内容特征，避免覆盖标签和评分形成的基础排序。
- 推荐分数只使用 Bangumi 的收藏状态、个人评分、条目标签、全站评分和站内关联数据；地区规则仅作候选资格过滤，不参与日本作品之间的排序。
- 所有类型只保留能由 Bangumi 标签、原名、制作机构或地区字段确认的日本作品；其他国家及来源不明的候选一律排除，不设破例。
- “暂时隐藏”只替换当前一批的该条目并提供 5 秒撤销，不写入画像，也不影响未来推荐分数。
- 使用 IndexedDB 缓存数据；收藏画像缓存 24 小时，候选缓存 3 天，人员信息缓存 30 天。
- “刷新画像”可立即忽略缓存，跟随最新收藏和评分重新计算。
- API 不可用时自动读取 Bangumi 站内收藏页、标签页和排行榜页。
- Shadow DOM 隔离样式，支持暗色模式、移动端、键盘操作和减少动态效果。

## 推荐算法

1. 把用户评分减去个人平均分与条目全站评分校准值，得到“超出预期的喜欢程度”。这样不会把单纯的高分热门条目误当成个人偏好。
2. 从标签、年代、条目形式、导演/作者、制作公司、脚本、音乐和声优构建稀疏特征；不同角色使用不同权重。
3. 对特征评分残差做带收缩的加权平均，并用 IDF 降低常见标签影响，避免只出现泛化标签。
4. 候选召回覆盖全站排名前 1000，以及个人前 12 个高权重标签各前 100 个条目，然后融合画像匹配、相似收藏、贝叶斯质量分和探索分。
5. 最后用 MMR 多样化，从高分候选中选出 5 个不过度重复的结果。

“适合度”和推荐理由都是本地确定性计算，不需要大模型。理由来自对最终得分贡献最大的特征，以及最相似的两个高评分收藏。

## 数据来源

优先使用 Bangumi API：

- `GET /v0/users/{username}/collections`
- `GET /v0/subjects`
- `POST /v0/search/subjects`
- `GET /v0/subjects/{subject_id}/persons`
- `GET /v0/subjects/{subject_id}/characters`

若跨域 API 被浏览器或网络策略拦截，组件自动回退到同域的收藏列表、标签和排行榜页面。人员信息只在 API 可用时补充，因此回退模式仍可推荐，但导演、制作公司和声优理由可能较少。

## 本地构建与测试

要求 Node.js 18 或更新版本，无第三方运行时依赖。

```powershell
npm run verify
```

构建产物为：

```text
dist/bangumi-personal-recommender.user.js
```

本地 UI 演示：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

随后打开 `http://127.0.0.1:8765/demo/`。演示页使用固定模拟数据，不访问账号。

## 安装与发布

开发时可以把构建产物导入支持 UserScript 的浏览器扩展进行测试。

作为 Bangumi 超合金组件发布时：

1. 打开 `https://bgm.tv/dev/app/create`，应用名填写“Bangumi 个性推荐”，类型选择“组件”。
2. 主页地址可以填写公开源码仓库；组件会访问 `api.bgm.tv`，因此需要勾选跨域请求声明。
3. 创建应用后点击“添加新版本”，把 `dist/bangumi-personal-recommender.user.js` 的完整内容粘贴到 JavaScript 编辑框并保存。
4. 前往 Bangumi 的“个人设置 → 超合金组件”启用最新版本，先以开发者身份验证。
5. 只有希望开放给其他用户时才选择“提交审核”；个人使用不需要提交审核。

Bangumi 会直接保存组件每个版本的 JavaScript/CSS，外部源码仓库用于主页、版本管理和审阅，并不是运行时依赖。

## 项目结构

- `src/core.cjs`：特征、画像、评分、解释和多样化算法。
- `src/component.js`：数据获取、缓存、交互和界面。
- `scripts/build.mjs`：生成单文件 UserScript。
- `tests/core.test.cjs`：核心算法测试。
- `demo/index.html`：Chrome 可视化测试页。

## 隐私与限制

- 个人数据只保存在当前浏览器的 IndexedDB/localStorage。
- 组件不修改 Bangumi 收藏、评分或标签。
- 公开收藏不足 5 个有效评分时不会强行给出低可信推荐。
- 新评分会在手动“刷新画像”后立即生效；不手动刷新时，最迟在画像缓存过期后的下一次生成中生效。
